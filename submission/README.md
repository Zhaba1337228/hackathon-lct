Конкурсное ТЗ ожидает подключение всех 17 целей. Текущий результат **не является полной приёмкой**. Цели 2, 5 и 10 остались неподключёнными. При буквальном правиле ближайшей границы их обязательный прямой выход повторно пересекает собственное здание; геометрические измерения и противоречие с §2.9 основного ТЗ показаны на слайде 11. Неполный поиск сам по себе не доказывает принципиальную невозможность подключения.

## Воспроизведение результата

1. Поднять сервис с `APP_CALCULATION_ROUTING_MODE=conservative-group-trunks`, `APP_CALCULATION_ROUTE_SEARCH_PARALLELISM=8`, `APP_CALCULATION_MAX_COMBINATIONS=512`, `APP_CALCULATION_MAX_VISIBILITY_VERTICES=300`.
2. Отдельно получить конкурсный файл, поместить его в `inputs/ТЗ/Датасет скорректированный.geojson` и запустить `node scripts/demo.mjs` с WGS84 bbox API. SHA-256 проверенного входа: `cffb7133419d93fe364a53015a7d3ead289f671cbfaf6f4befe87f2a21914130`.
3. По завершении запустить `node scripts/report_job.mjs JOB_ID INPUT.geojson REPORT.json`; проверить `rank1=14/17` и стоимость. В отчёте v28 зафиксированы ID образа/JAR и пик памяти контейнера 2 402 369 536 байт. Сверка экспорта не является отдельной проверкой всех инженерных отступов: их выполняет серверный `VariantValidator` до публикации.

Сценарий показа — [docs/demo.md](../docs/demo.md). Сводка алгоритма и ограничений — [docs/algorithm.md](../docs/algorithm.md), [docs/limits.md](../docs/limits.md).
