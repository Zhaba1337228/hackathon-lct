# Трассировка тепловых сетей

Сервис моделирует предварительное подключение новых зданий к существующей теплосети. Он принимает GeoJSON, ищет допустимые общие стволы и отводы, независимо проверяет геометрию и инженерные ограничения, рассчитывает диаметр, длину, стоимость и показывает до трёх вариантов на карте. Результат выгружается как GeoJSON в WGS84.

> **Статус конкурсного набора.** Полный API-прогон актуальной сборки от 29.09.2026 подключил **14 из 17** точек. [Комплект сдачи](submission/README.md) содержит презентацию и скринкаст; конкурсный датасет и производный GeoJSON в публичный Git не включены. Цели 2, 5 и 10 остались неподключёнными; штраф за них включён в итоговую стоимость. Это частичный результат, не приёмка 17/17.

## Быстрый запуск

Нужны Docker Desktop с работающим Docker Engine и свободный порт. Из корня проекта в PowerShell:

```powershell
$env:APP_HOST_PORT='8100'
docker compose up -d --build
```

Откройте `http://localhost:8100/`. Если порт 8080 свободен, можно не задавать `APP_HOST_PORT` и открыть `http://localhost:8080/`. Проверка сервиса: `http://localhost:8100/api/health`; OpenAPI: `http://localhost:8100/swagger-ui.html`. Первый запуск собирает Java-приложение и поднимает PostGIS. Данные заданий хранятся в Docker volumes.

Для конкурсного экспериментального режима общих стволов перед запуском Compose задайте:

```powershell
$env:APP_CALCULATION_ROUTING_MODE='conservative-group-trunks'
$env:APP_CALCULATION_ROUTE_SEARCH_PARALLELISM='8'
$env:APP_CALCULATION_MAX_COMBINATIONS='512'
docker compose up -d --build
```

Этот режим ищет несколько групповых деревьев и может работать минуты. Стандартный режим Compose — `visibility`; переключение режима требует пересоздания контейнера. Конкурсный прогон 14/17 использовал 8 независимых поисков и 512 комбинаций; нагрузочный профиль нескольких одновременных пользователей не подтверждён.

## Работа в интерфейсе

1. Загрузите отдельно полученный конкурсный GeoJSON или свой GeoJSON FeatureCollection в WGS84. Конкурсный файл не публикуется в этом репозитории; для автоматического сценария поместите его в `inputs/ТЗ/Датасет скорректированный.geojson` либо передайте свой путь аргументом.
2. Выберите область на карте или введите bbox `[запад, юг, восток, север]` в WGS84.
3. Запустите расчёт. Карта показывает здания, сети, источник тепла, пробные ветви и рост проверенного дерева.
4. Сравните варианты: подключения, длину, строительство, штраф и итоговую оценку. Скачайте GeoJSON через интерфейс или API.

Все отсутствующие в выданном варианте точки перечисляются в `unconnectedTargetIds` и входят в штраф `100 000 000 + 500 000 × flow_tph` за точку. `unsearchedTargetIds` — подмножество этого списка, где поиск остался неполным. Такая метка не означает доказанную техническую невозможность подключения.

## API и автоматический сценарий

| Операция | Назначение |
|---|---|
| `POST /api/jobs` | Загрузка и проверка GeoJSON |
| `GET /api/jobs/{jobId}` | Состояние задания |
| `GET /api/jobs/{jobId}/view/extent` | Bbox входа в WGS84 |
| `POST /api/jobs/{jobId}/calculate` | Запуск с JSON `{"bbox":[west,south,east,north]}` |
| `GET /api/jobs/{jobId}/variants` | Сводка, причины поиска, стоимость и ранжирование |
| `GET /api/jobs/{jobId}/view` | Постраничные объекты для карты |
| `GET /api/jobs/{jobId}/export` | Итоговый GeoJSON FeatureCollection |

Автоматический сценарий на конкурсном файле (запускает **полный расчёт**):

```powershell
$env:HEAT_DEMO_BASE_URL='http://localhost:8100'
node scripts/demo.mjs
```

См. [сценарий демонстрации](docs/demo.md). В `scripts/demo.mjs` координаты и ID конкурсного файла не зашиты: область запрашивается у API. Экспорт сохраняется в `artifacts/demo/` и не входит автоматически в комплект сдачи до проверки.

## Проверка и устройство проекта

```powershell
.\mvnw.cmd verify
node --test src/test/js/*.test.mjs
node --check src/main/resources/static/map.js
docker compose config
```

Java 11 / Spring Boot 2.6.3, PostGIS 16 и Leaflet 1.9.4. Геометрия расстояний вычисляется в EPSG:32637, API и экспорт используют WGS84. `VariantValidator` отдельно проверяет построенные варианты перед оценкой и выдачей. В публичный Git входят код, документация, презентация и скринкаст; локальные спецификации `.kiro/`, входные данные, результаты экспериментов и сборка исключены через `.gitignore`.
