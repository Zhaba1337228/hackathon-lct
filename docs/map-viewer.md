# Просмотр карты и расчёт вариантов

Карту отдаёт то же Spring Boot приложение, что и API. Сборка JavaScript и сетевое подключение к CDN не требуются; Leaflet 1.9.4 поставляется вместе со статическими ресурсами приложения.

## Запуск

Для запуска с PostgreSQL/PostGIS:

```powershell
docker compose up --build
```

Откройте `http://localhost:8080/` или порт, заданный `APP_HOST_PORT` (см. [README](../README.md)). Для локального запуска приложения при доступной БД используйте:

```powershell
.\mvnw.cmd spring-boot:run
```

Загрузите GeoJSON или откройте задание по его UUID. Карта получает исходную область набора и постранично запрашивает только геометрии, пересекающие текущие границы просмотра. Перемещение и масштабирование меняют лишь область просмотра. Для расчёта зафиксируйте видимые границы кнопкой «Взять текущую область карты» и запустите расчёт. После завершения можно выбрать до трёх вариантов; щелчок по линии или узлу показывает инженерные свойства объекта.

Интерфейс отображает существующие теплосети, камеры, источники, точки подключения и ограничения разными слоями. Участки, рассчитанные способом `special`, рисуются пунктиром. Ручного инструмента перемещения геометрии нет; расчёт и экспорт используют только серверный результат.

В карточке каждого варианта показаны типизированные ID подключённых целей, длина и оценка стоимости строительства с отдельным штрафом за все отсутствующие в варианте цели. `unsearchedTargetIds` — диагностическое подмножество `unconnectedTargetIds`; по нему поиск был неполным, но штраф за отсутствие в варианте включён в итог. Варианты сравниваются с вариантом №1 по метрикам, оценке и набору подключений. Цели вне bbox отмечаются отдельно; для проверки расширьте область и создайте новое задание. Отсутствие найденного маршрута не означает техническую невозможность подключения.

## API карты

- `GET /api/jobs/{jobId}/view/extent` возвращает `bbox` в WGS84 для начального охвата карты.
- `GET /api/jobs/{jobId}/view?bbox=west,south,east,north&limit=500` возвращает исходные GeoJSON-объекты, пересекающие viewport.
- Чтобы дополнительно получить один вариант, укажите `variantId`. `inputCursor` и `variantCursor` независимо продолжают страницы исходных объектов и результата.
- Максимальный размер страницы — 500 объектов на слой. Сводки и состояние задания продолжают отдаваться маршрутами `/api/jobs/{jobId}` и `/api/jobs/{jobId}/variants`.
- Сводка варианта содержит `connectedTargetIds` и `unconnectedTargetIds` с исходными типами ID; верхний уровень ответа содержит попытки поиска `targetSearches` и `unsearchedTargetIds`.

Результат расчёта индексируется в PostGIS до перехода задания в `SUCCEEDED`; запрос карты не читает полный экспортный файл. После начала TTL-очистки карта, сводки и экспорт отвечают `410 RESULT_EXPIRED`. Результаты очищаются по тому же TTL, что входные данные и файлы задания.
